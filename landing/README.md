# Zenbree landing

The marketing page, a static Astro site. It has no runtime: the container serves `dist/` with nginx on port 8080.

```
pnpm install
pnpm dev       # http://localhost:4321
pnpm check     # astro check
pnpm lint      # Biome + lint/check.mjs (Tailwind scale, no plain CSS)
pnpm test      # lint/check.test.mjs
pnpm build     # dist/
```

`PUBLIC_APP_URL` is a build-time value, the base URL of the Zenbree app (default `http://localhost:3000`). Sign-up, sign-in, terms and privacy links derive from it in `src/content.ts`. nginx sends any path the site does not have to the same path on that URL (308), so links from when the app lived on zenbree.com still work. Changing it needs a rebuild: in compose, `PUBLIC_APP_URL=… docker compose build landing`.

Copy lives in `src/i18n/<language>.ts` (`it`, `en`, `es`, `fr`), each typed by `Content` in `src/content.ts` (a missing key fails `pnpm check`). Italian is served at `/`, the others at `/en/`, `/es/` and `/fr/`.

Styles are Tailwind 4 classes on the elements. The design tokens (colours, type sizes, shadow, breakpoints, fonts, the dark scheme) live in `src/styles/theme.css`; a class bundle used in several places lives in `src/styles/classes.ts`. The page follows `prefers-color-scheme` only: light values are in `@theme`, dark values in the `@media` block at the end of `theme.css`. Breakpoints are the variants `tablet:` and `phone:`.

`pnpm lint` enforces the same rules as the web, with `lint/check.mjs` (the web's Oxlint rules do not read `class="…"` in `.astro`):

- no arbitrary Tailwind values: use a scale step, a token from `theme.css` or a stock utility (the rule is generated by `web/lint/gen-tailwind-scale.mjs`, see `web/lint/README.md`);
- no `<style>` element, no `style=` attribute, no `.css` file except `theme.css`;
- `theme.css` holds only `@import`, `@theme`, `@font-face`, `@custom-variant`, `@utility` and the dark `@media` block;
- an `@utility` must be in `APPROVED_UTILITIES`. Do not edit that list: fix the markup, or ask the user.
