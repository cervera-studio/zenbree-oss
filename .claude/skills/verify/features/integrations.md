# Integrations

A signed-in user connects the accounts Zenbree sends from on Settings › Integrazioni: Gmail or Outlook mailboxes through OAuth, and a LinkedIn profile through Unipile. Each connection shows a status pill and the action that fits it. LinkedIn asks for a risk acknowledgement before it connects.

## Sub-features

- `integrations-mailbox-rows` shows one row per connected or broken mailbox account (a client may have several of one provider, #935), with `Collegata` or `Da ricollegare`, `link "Mittenti"` and `button "Scollega"` or `button "Ricollega"`.
- `integrations-mailbox-add` shows one button for each provider, also when the client already has a mailbox of it: `button "Collega una casella <provider>"` while the client has no mailbox of any provider, else `button "Collega un'altra casella <provider>"` (also for a provider the client has no mailbox of). Without an OAuth client the button is `[disabled]` and `Non ancora disponibile su questo server.` follows it.
- `integrations-mailbox-disconnect` revokes a mailbox through `alertdialog "Scollegare questa casella?"`.
- `integrations-oauth-notice` shows the `?mailbox=connected` and `?mailbox=failed` result banners (`status`).
- `integrations-linkedin-risk` gates `button "Collega"` and `button "Accedi con email e password"` behind the risk checkbox.
- `integrations-linkedin-credentials` shows the email and password form, then the verification code step when LinkedIn asks for one.
- `integrations-linkedin-in-use` refuses a LinkedIn account that another user already connected: the form shows `status` `Questo account LinkedIn è già collegato a un altro account Zenbree.` and the API answers 409 `INTEGRATIONS.ALREADY_CONNECTED_ELSEWHERE` with no row (#317).
- `integrations-hubspot` shows `region "HubSpot"` (a dashed card until it is connected) with `Non collegato`, `Collegato` or `Da ricollegare`, the portal domain, and `button "Collega"` or `button "Scollega"` in the card's head row (#120). The design draws it as a `Presto` stub; the real card keeps its working buttons.
- `integrations-linkedin-account` shows the initials avatar, the account label, `Premium` when set, and `button "Scollega"`.

## How to get to it (user POV)

- Choose `link "Impostazioni"` in the sidebar, then the tab `link "Integrazioni"`. It opens `/settings/integrations`.
- `link "Collega una casella"` on [senders](senders.md) leads here, and so does `link "Ricollega"` on a broken sender. Pausing a mailbox and setting its hours are by account id on the senders page; this page connects by provider and disconnects one account by its id.
- The OAuth callback redirects here with `?mailbox=connected` or `?mailbox=failed`.

## Gotchas

- Mailbox buttons are `[disabled]` when the server has no OAuth client for the provider, and the row says `Non ancora disponibile su questo server.`. The stack has none, so `Ricollega` and the add buttons render but cannot start the consent flow: report that part as skipped.
- The hosted link redirects back with `?linkedin=connected` or `?linkedin=failed`, but the page reads neither and shows no LinkedIn banner. A hosted connect refused as in use leaves the pill at `Non collegato` with no reason (the `ponytail:` in `api/app/linkedin/api.py`).
- A connected LinkedIn row hides the risk callout. Delete the `unipile` row (or disconnect) to see the callout again. Disconnecting calls Unipile, which the stack lacks: `button "Scollega"` opens `alertdialog "Scollegare LinkedIn?"`, and its confirm shows the toast `Impossibile scollegare LinkedIn. Riprova.` with the row unchanged. Seed and delete rows directly.
- The daily LinkedIn invite limit is not shown: the API does not return it.
- HubSpot's consent, token exchange and CRM reads need a real app and portal: the stack has neither, so a completed connection and a real gate verdict are skipped. Seed rows as above.
