# Settings profile

Settings opens on the profile page (`/settings`). The user sees their account card (photo or initials, name, "email · company"), adds, replaces or removes their photo, edits their name and company, reads the verified email and asks to change it, picks the interface language, theme and time zone, sees which sign-in methods are linked, changes their password behind a toggle, signs out their other devices, and deletes their own account from the danger zone. A tab bar links the other settings pages: Profilo, Notifiche, Mittenti, Integrazioni, Memoria, Esclusioni, Cliente, Team, API key and Crediti (the last two for an admin of the organization only).

## Sub-features

- `profile-photo` uploads, replaces and removes the profile photo (#503). The account card and the account menu in the sidebar show it, or the initials without one.
- `profile-name` saves a new display name (and the company, when the user has one) with one `button "Salva"`.
- `profile-company` edits the company name, which lives in the onboarding business profile. Hidden until the user has a profile.
- `profile-email` asks to change the email: `textbox "Nuova email"` and `button "Cambia email"` send a confirmation to the current address first.
- `profile-timezone` saves the time zone that dates use, from the native `combobox "Fuso orario"`.
- `profile-password` changes the password from the collapsed `Accesso` row; a wrong current password is rejected.
- `profile-sessions` signs out every other device behind a confirm dialog; this device stays signed in.
- `profile-delete` deletes the user's own account (#341) after typing `ELIMINA` (`DELETE` in English); the organization keeps what they created, as for an admin's delete (#333, [team](team.md)).
- `profile-language` switches the interface language.
- `profile-theme` switches between light, dark and system.
- `settings-tabs` lists the settings pages as links.
- `settings-phone-menu` below 760 px replaces the tabs: `/settings` shows only the menu, each page opens full screen under a back link.

## How to get to it (user POV)

- Choose `link "Impostazioni"` in the sidebar, the profile `link "<name> <company or email>"` in the sidebar foot, or `menuitem "Profilo e impostazioni"` in `button "Menu account"`. The last two open `/settings/profile`, so on a phone they land on the profile, not the menu.
- The tabs are links in `navigation "Impostazioni"`. `Crediti` opens `/billing`.

## Driving it with bin/browser

Preconditions:

- A seeded user, signed in and past onboarding.
- For the company field, a saved business profile. `Salta per ora` leaves none, so the field is absent. Setup only: `curl -X PUT -H "Authorization: Bearer $T" -H 'content-type: application/json' "$VERIFY_API/v1/onboarding/profile" -d '{"company_name":"Ritmo Sales","summary":"s","solution":"s"}'`, with `$T` from `bin/browser eval "fetch('/api/auth/token').then(r => r.json()).then(j => j.token)"`.

- **Open.** `bin/browser click link "Impostazioni"`, then `bin/browser wait heading "Profilo"`. `ax` shows `region "Il tuo account"` (the avatar, name, `email · company`, for an admin of the organization the tag `Admin`, then `button "Aggiungi una foto"` and the hint `JPEG, PNG o WebP, fino a 5 MB.`); `region "Dati personali"` with `textbox "Nome"`, `textbox "Azienda"` (with a profile), `textbox "Email"` with the text `Verificata`, `textbox "Nuova email"` and `button "Cambia email" [disabled]`; `region "Preferenze"` with `radiogroup "Lingua"` (`radio "English"`, `radio "Italiano"`, `radio "Español"`, `radio "Français"`), `radiogroup "Tema"` (`radio "Chiaro"`, `radio "Scuro"`, `radio "Sistema"`) and `combobox "Fuso orario"`; and under `region "Accesso"` the `button "Cambia password"` and `button "Esci dagli altri dispositivi"`. `button "Salva"` is `[disabled]` until a field changes.
- **Photo.** The API stores the photo in an R2 bucket, so the stack needs a stand-in for its S3 API: a few-line `http.server` on the host, kept outside the repo, that stores PUT bodies in memory, answers GET of a key (404 when absent), DELETE (204) and `GET /<bucket>?list-type=2&prefix=` with a `<ListBucketResult><IsTruncated>false</IsTruncated><Contents><Key>…</Key><LastModified>…</LastModified></Contents></ListBucketResult>`. It checks no signature. The photo URL starts with `API_PUBLIC_BASE_URL`, which must be the address `bin/stack env` later prints as `VERIFY_API`. `$VERIFY_API` does not exist before that, so build the address from the port in the same command: `export VERIFY_API_PORT=18000` (or your port; a prefix on the `bin/stack up` line expands too late), then `API_PUBLIC_BASE_URL=http://localhost:$VERIFY_API_PORT bin/stack up`. Then give the api a compose override with `R2_ENDPOINT: http://host.docker.internal:<port>`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` (any values) and `R2_PHOTOS_BUCKET`, and run `API_PUBLIC_BASE_URL=$VERIFY_API bin/stack compose -f <override>.yml up -d api`: compose reads the variable each time it creates the api container. Without them the upload shows `PHOTO.UNAVAILABLE`'s text. `bin/browser upload "input[type=file]" <file.png>`, then `bin/browser wait button "Cambia foto"`: `button "Rimuovi"` appears, and `bin/browser eval "[...document.querySelectorAll('img')].map(i => i.src)"` lists `$VERIFY_API/v1/avatars/<user id>/<token>` twice, the account card and the sidebar's account menu. `SELECT image FROM "user"` prints the same URL. After a reload both still show it. `bin/browser click button "Rimuovi"`, `bin/browser wait button "Aggiungi una foto"`: no `img` is left, both places show the initials, `image` is NULL and the stand-in logs a DELETE of the key. At 390 px the buttons sit on their own line under the name.
- **Name and company.** `bin/browser fill textbox "Nome" "Adm Renamed"`, `bin/browser fill textbox "Azienda" "Globex Srl"`. A `status` reads `Modifiche non salvate`. `bin/browser click button "Salva"`: the `status` reads `Salvato.` and `bin/stack psql -tAc "SELECT name FROM \"user\" WHERE email='<email>'"` prints the new name. `bin/stack psql -tAc "SELECT profile FROM business_profiles"` shows the new `company_name` and the other profile fields unchanged.
- **Email change.** `bin/browser fill textbox "Nuova email" "<new>@verify.local"`, `bin/browser click button "Cambia email"`: a `status` reads `Controlla il tuo indirizzo attuale: conferma lì il cambio, poi verifichiamo il nuovo.` The confirmation goes by email, so report the change itself as skipped.
- **Time zone.** `bin/browser select combobox "Fuso orario" "America/New_York"`: the value saves on change, and `bin/stack psql -tAc "SELECT \"timeZone\" FROM \"user\" WHERE email='<email>'"` prints `America/New_York`. The first option, `Browser (<zone>)`, clears the saved zone (`NULL`). The list holds only zones the browser knows, so an unknown zone cannot be picked; a saved alias that the browser does not list still shows as the current option.
- **Password.** `bin/browser click button "Cambia password"` (it becomes `button "Annulla"`), fill `textbox "Password attuale"` with a wrong value and `textbox "Nuova password (almeno 8 caratteri)"`, click `button "Salva password"`: an alert reads `La password attuale non è corretta.` With the right current password the form closes and a `status` reads `Password aggiornata.` Compare `SELECT password FROM account WHERE "providerId"='credential'` before and after, and sign in with the new password later.
- **Other devices.** Open a second session: `curl -X POST "$VERIFY_WEB/api/auth/sign-in/email" -H 'content-type: application/json' -H "origin: $VERIFY_WEB" -d '{"email":"<email>","password":"<password>"}'` (`SELECT count(*) FROM session` prints 2). `bin/browser click button "Esci dagli altri dispositivi"`: an `alertdialog "Uscire dagli altri dispositivi?"` appears. `bin/browser click button "Esci dagli altri"`: a toast reads `Gli altri dispositivi sono stati disconnessi.`, the count prints 1 and the page stays signed in.
- **Delete the account.** `region "Zona pericolosa"` has `button "Elimina account"`. Click it: `alertdialog "Eliminare il tuo account?"` lists what stays and what goes, with `textbox "Scrivi ELIMINA per confermare"` and the dialog's `button "Elimina account" [disabled]`. `bin/browser fill textbox "Scrivi ELIMINA per confermare" "elimina"`: still `[disabled]`. `"ELIMINA"`: enabled; `bin/browser click button "Elimina account"` (the trigger behind the dialog is hidden, so one match), `bin/browser wait-url /auth/sign-in`. Read back: the `"user"`, `member` and `session` rows are gone; a client or list they created in a team has `user_id` NULL; their sender is `disconnected`/`owner_deleted` with no token and no `project_senders` row; their own organization stays (no members) and `deleted_member_orgs` names it and every team; `bin/stack logs api` shows `POST /v1/me/before-delete` 200 before the delete. Signing in again is 401. Setup for the team part: a second seeded user, then by SQL a `member` row in their organization and a project, list and sender of the deleted user's in it, as in [team](team.md#driving-it-with-binbrowser).
- **Delete refused: last admin.** The founder of an organization with another member (setup: a `member` row for a second seeded user) and no other admin: the same steps end on `/settings` with the toast `Sei l'unico amministratore di un team con altri membri: nomina amministratore un altro membro, poi elimina l'account.`; `bin/stack logs api` has `POST /v1/me/before-delete` 409, and the user, their sessions and their `account` row are unchanged.
- **Delete stops billing.** A user who is the only member of their organization, with a live plan and auto top-up (setup: the `subscriptions` and `auto_topups` inserts in [billing](billing.md#driving-it-with-binbrowser), `enabled` true). Stripe has no key in the stack, so run [stripe-mock](https://github.com/stripe/stripe-mock) at the boundary: a compose override adds `stripe-mock: {image: stripe/stripe-mock:latest}`, and gives `api` `STRIPE_SECRET_KEY: sk_test_verify`, `PYTHONPATH: /stripe-site` and a read-only mount of a directory holding a `sitecustomize.py` with `import stripe; stripe.api_base = 'http://stripe-mock:12111'` (keep both files outside the repo); `bin/stack compose -f <override>.yml up -d stripe-mock api` after `bin/stack up`. Deleting reads back `subscriptions.status` `canceled` and `auto_topups.enabled` `f`, and `docker logs <project>-stripe-mock-1` has `DELETE /v1/subscriptions/<id>`. With the container stopped (`docker stop`) the delete ends on the toast `Eliminazione non riuscita. Riprova.` (502 `ACCOUNT.BILLING_CANCEL_FAILED`, log `account.delete.cancel_failed`), and the user, the plan (`active`) and auto top-up (`t`) are unchanged. A team's plan is never cancelled while it has other members. A plan already over at Stripe (gone, `canceled` or `incomplete_expired`, the webhook never landed) does not block the delete: the api logs `account.delete.already_ended` and marks the row `canceled`. To drive it, swap stripe-mock in the override for a few-line `http.server` that answers every request `404 {"error":{"type":"invalid_request_error","code":"resource_missing"}}`.
- **Admin delete, same rules.** As `dev@zenbree.local` (back-office admin in the dev seed) or after `bin/stack make-admin`, `bin/browser eval "fetch('/api/auth/admin/remove-user',{method:'POST',headers:{'content-type':'application/json'},body:JSON.stringify({userId:'<id>'})}).then(async r=>r.status+' '+await r.text())"`: a team's last admin is `409 {"code":"ACCOUNT.LAST_ADMIN",…}` with their sessions and `account` row intact (they can still sign in); a non-string id (`{userId: ['<id>']}`, `{userId: 123}`) is `400 INVALID_USER_ID` before anything runs (Better Auth would coerce it); the admin's own id is Better Auth's `400 YOU_CANNOT_REMOVE_YOURSELF` with no `before-delete` call; a sole member's plan is cancelled as above; the api log has `POST /v1/admin/users/<id>/before-delete`. `POST $VERIFY_API/v1/me/before-delete` with one user's JWT and another's `user_id` is 403 `ACCOUNT.NOT_YOURS`. The database holds both rules too: `bin/stack psql -tAc "DELETE FROM \"user\" WHERE id='<last admin>'"` fails with `ACCOUNT.LAST_ADMIN` (`ACCOUNT.STILL_BILLING` for a sole member with a live plan or auto top-up on). The back office has no delete button yet: the endpoint's error is what an admin sees.
- **Linked accounts.** A Google or Microsoft sign-in shows a row `Google` or `Microsoft` with `Collegato`. The stack has no OAuth, so setup only: `INSERT INTO account (id,"accountId","providerId","userId","createdAt","updatedAt") SELECT gen_random_uuid(),'g-1','google',id,now(),now() FROM "user" WHERE email='<email>'`, then reload.
- **Theme.** `bin/browser click radio "Scuro"`. `bin/browser eval "document.documentElement.classList.contains('dark')"` prints `true`. With a radio focused, `bin/browser press ArrowDown` selects the next option.
- **Language.** The group has four radios: `English`, `Italiano`, `Español`, `Français`. `bin/browser click radio "English"`, reload. The heading is `Profile` and the group is `radiogroup "Language"`. `radio "Español"` gives the heading `Perfil` and `radiogroup "Idioma"`; `radio "Français"` gives `Profil` and `radiogroup "Langue"`. `SELECT locale FROM "user" WHERE email='<email>'` follows the choice at the click, before the reload: the settings action saves it, and opening the app never changes it (#795). Switch back with `bin/browser click radio "Italiano"`.
- **Phone menu.** `bin/browser viewport 390 844`, `bin/browser goto "$VERIFY_WEB/settings"`. `ax` shows `navigation "Impostazioni"` with ten `link`s in a `list` for an admin of the organization (`Profilo` … `Crediti`), eight for a member and no profile form. `bin/browser click link "Mittenti"`, `bin/browser wait heading "Mittenti"`: no tabs, `link "Tutte le impostazioni"` above the page. Click it, `bin/browser wait-url /settings`, then `bin/browser click link "Profilo"` lands on `/settings/profile` with `heading "Profilo"` visible. For a 390-wide shot: `bin/browser screenshot <file> --width 390 --height 2200` (the window floor is 500).

## Gotchas

- Headless Chrome reports `prefers-color-scheme: dark` when macOS is in dark mode, so `Sistema` renders dark there. Click `radio "Chiaro"` when a light screenshot matters.
- The language radios write the `NEXT_LOCALE` cookie, the same one `bin/browser locale` sets. Switch back to Italian before following other recipes.
- A password change revokes the user's other sessions. The current one stays signed in. The company field saves the whole profile through `PUT /v1/onboarding/profile`, so it also syncs the profile exclusions and rewrites the Memory bullet (see [onboarding](onboarding.md)); segments are untouched.
- Email shows `Verificata` only when `emailVerified` is true. The email change needs a sent email to finish: the stack sends none, so only the request is drivable.
- A user with no business profile (the seeded `dev@zenbree.local`, or one who chose `Salta per ora`, which leaves a row with a NULL `profile`) never sees `textbox "Azienda"`, before or after a name save, and can save the name twice in a row without a reload (#238).
- At 1440 the tabs stay and `/settings` is still the profile page; `/settings/profile` shows the same page with `Profilo` current.
- Better Auth refuses a delete from a session older than a day (`SESSION_EXPIRED`): the toast reads `Per sicurezza, esci e accedi di nuovo, poi riprova.` and nothing is deleted. Not driven (a fresh seeded session is always young); unit-tested in `delete-account.test.tsx`.
