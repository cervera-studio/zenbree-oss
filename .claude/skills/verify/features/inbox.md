# Inbox

Risposte (`/inbox`, C4) has three flush columns under the topbar (`navigation "Percorso"`, `Risposte`): the filter rail, the thread list (newest first by default, `GET /v1/inbox?sort=oldest` reverses it; email and LinkedIn) and the open thread. Each column scrolls on its own. A thread shows the sender, their role and company, the campaign link, the campaign steps that reached them, their message, the answers sent from the inbox, the label control and the answer box (#187) with the agent's draft. The rail counts each filter and adds `Da leggere` (not opened yet) and `Disiscrizioni`. Auto-replies (they pause the person's sequence until the return date, #346) and opt-outs show their state instead of a label; an opt-out thread says the person asked not to be contacted and has no reply box. Filters by label and channel live in the URL. On a phone (M5) the rail becomes a row of chips and a thread opens alone at `?m=`.

## Sub-features

- `inbox-list` lists threads newest first and opens the first (or `?m=<id>`) in the thread pane, or shows the C4b empty state with `link "Vai alle campagne"`.
- `inbox-states` shows `Risposta automatica` and `Disiscrizione` as states; an opt-out has no reply box.
- `inbox-mailbox-reply` (#1165) a reply read from the sending mailbox (no Reply-To domain) appears in the list (labelled only with an LLM key on the worker, else `Senza etichetta`); recipe in [campaigns](campaigns.md), Replies from the mailbox.
- `inbox-filter` filters by label (`?label=`) and channel (`?channel=`); the two compose.
- `inbox-relabel` changes a reply's label and records it as a manual label.
- `inbox-phone` opens one thread full screen at `?m=<id>` below 760 px.
- `inbox-loading` is the C4c skeleton (`loading.tsx`).
- `inbox-read` opening a thread at `?m=` marks it read; the desktop's default first thread is not marked.
- `inbox-campaign` (#346) `/inbox?campaign=<id>` filters rows and counts to one campaign, with a removable chip.
- `inbox-pause` (#346) an auto-reply thread says the person's sequence is paused and when it restarts.
- `inbox-reminder` (#346) a «Non ora» reply keeps a reminder; when it is due the thread is unread again.
- `inbox-unverified` (#421) a reply whose DMARC check failed shows the pill `Non verificato` in the list and a warning notice in the thread; a pass or an unchecked reply shows neither.
- `inbox-regenerate` (#836, #865) `button "Rigenera"` on the answer box (`Scrivi una bozza` when the reply has no draft yet) calls `POST /v1/inbox/<id>/draft` and puts the new draft in the box; the replaced text stays one click away (`button "Ripristina il testo precedente"`, which swaps the two). While the call runs the box is read-only and both buttons are disabled. After a new draft, open another thread and go Back (`history.back()`): the box shows the new draft, not the one the page first loaded (the call clears the router cache with `router.refresh()`). A `not_interested`, unlabelled or unverified reply has no button (the API would answer 409 `INBOX.NO_DRAFT`); an unknown id is 404; a provider failure, or no answer within 30 s, is 502 `INBOX.LLM_FAILED` with the old draft kept.
- `inbox-sort` (#865) `link "Mostra prima le più vecchie"` in the list head adds `?sort=oldest` (`GET /v1/inbox?sort=oldest`) and the head reads `… · le più vecchie in alto`; `link "Mostra prima le più recenti"` drops it. The filters and the pager keep it.
- `inbox-reply` sends an answer from the box (`button "Invia risposta"`), or says why there is no box (opt-out, exclusion, no mailbox, no LinkedIn account).

## How to get to it (user POV)

- Choose `link "Risposte"` in the sidebar. It opens `/inbox`.

## Gotchas

- Only the open thread has a `combobox "Cambia etichetta"`; auto-replies and opt-outs have none.
- **Answering (#187).** The stack has no real mailbox and no Unipile, so the UI send cannot succeed here. A worker script can drive `inbox_reply.send` to `sent` with the transport stubbed: set `dispatcher._access_token` to an async function returning `'stub-token'`, replace `mailbox_sender.send` with an async recorder `(provider, *, access_token, raw, thread_id='')` that parses `raw` with `email.message_from_bytes` and returns `ok(ProviderReceipt(message_id='stub-1', thread_id=''))` (`app.core.errors.ok`, `app.core.mail_threading.ProviderReceipt`), and block `httpx.AsyncClient.send` so nothing leaves the worker. Then run `asyncio.run(inbox_reply.send(project_id, message_id, 'text'))` inside `with acting_as(org_id, user_id):` (`app.core.scope`), which is the scope `POST /v1/inbox/{id}/reply` runs in. `outreach_inbox_replies` shows `sent`, and the recorded message holds `From`, `In-Reply-To`, `Reply-To` and `List-Unsubscribe`. Needs a connected mailbox linked to the project (below); send no real mail. The SQL tests (`api/tests/test_inbox_reply_sql.py`) fake the provider the same way. What the stack shows without the stub: insert a `user_oauth_connections` row linked to the client in `project_senders` (as in [senders](senders.md); `provider 'google'`, `refresh_token_encrypted 'x'`, `granted_scopes ARRAY['https://www.googleapis.com/auth/gmail.send']`, `account_label`, `created_at now() - interval '60 days'`). With one mailbox the reply goes from it. The thread then shows `textbox "Bozza dell'agente · da <address>"` when `draft_body` is set (the `draft_reply` task writes it after labelling; it needs an LLM key, so set it with psql), or `La tua risposta · da <address>`. With `daily_limit = 1` and one `outreach_inbox_replies` row `sent` today, `Invia risposta` shows `La casella ha raggiunto il limite di invii di oggi. Riprova domani.`; without the cap the fake token fails, the mailbox goes to `error` and the box gives way to `Nessuna casella collegata da cui rispondere…`. An address in `exclusions` shows `Questa persona è nelle tue esclusioni…`; a LinkedIn reply without a Unipile account shows `Collega il tuo account LinkedIn…`. Insert `rfc_message_id`/`sender_provider_id` on seeded inbound rows when you need them: a LinkedIn row without `sender_provider_id` shows `Non c'è un indirizzo a cui rispondere.` instead of the LinkedIn notice.
