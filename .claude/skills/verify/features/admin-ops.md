# Admin transcript, costs and jobs

The back office screens A3–A5 of the 2 Oct handoff: a chat transcript with a cost summary, the costs dashboard and the jobs list. The rail shows two counters: jobs failed or waiting on input in the last 24 hours (`link "Job N job falliti o in attesa di input nelle ultime 24 ore"`, #352) and kill switches on (`link "Impostazioni N interruttori accesi"`). Switches themselves are in [admin settings](admin-settings.md), users in [admin users](admin-users.md).

## Sub-features

- `admin-transcript` (`/admin/chat-sessions/<id>`): messages with role, time and credits, the ask_user question as its own block («Domanda all’utente», with its options), tool calls as disclosures with their vendors (`apollo → hunter`, #352; nothing for calls saved before it) summary and credits (an enrich batch whose lookups all failed reads «N ricerche non riuscite, da riprovare», not «0 email», #548), and the «Riepilogo» / «Costo per noi» cards (credits spent, returned and net, LLM and vendor cost, estimated revenue and margin) with `button "Apri la sua vista (impersona)"`.
- `admin-transcript-views`: `link "Apri tutti i dettagli"` (`?open=1`) opens every tool call, `link "Solo chiamate ai tool"` (`?tools=1`) hides message text. The active one has `aria-current="true"`.
- `admin-costs` (`/admin/costs`): six KPI cards, the daily chart with `link "Mostra tabella"` (`?view=table`, and back with `Mostra grafico`), contact providers by success rate with a `disattivato` tag when their kill switch is on, and the per-user table with `link "Costo più alto"` / `link "Margine più basso"` (`?sort=margin`).
- `admin-costs-error`: when the API does not answer, an `alert` with «API non raggiungibile», the request line and `503 INTERNAL.SERVICE_UNAVAILABLE`, and `link "Riprova"`.
- `admin-jobs` (`/admin/jobs`): status chips with counts (`link "Fallito 1"` → `?status=failed`), a table with one row per job, whose `button "Dettagli <8 chars of the id>"` (`aria-expanded`) opens the brief, the refund note («3 righe non consegnate, 14 crediti resi», #352), the error, the stages with done/units and elapsed time (none on jobs from before #352) and `Vedi utente` / `Apri la chat`.
- `admin-jobs-filter` (`/admin/jobs?user=<id>`, `?job=<id>`): the user detail page's `Job` button and the transcript's job link open Jobs filtered; «Filtrato:» shows a chip per filter (`Utente <email>`, `Job <8 chars>`) whose `link "Togli il filtro …"` clears it and keeps the status. `?job=` opens that job's row whatever its age, in any letter case.

## How to get to it (user POV)

- In the back office rail (`navigation "Backoffice"`), `link "Costi"` opens `/admin/costs` and the `Job` link opens `/admin/jobs`.
- A transcript opens from a user's `Sessioni chat N` tab ([admin users](admin-users.md)) or from a job in the jobs list; its job link opens the jobs list filtered on that job.

## Driving it with bin/browser

Preconditions: `adm@verify.local` (admin) and `ale@verify.local` seeded, then `bin/stack psql -f - < features/admin-ops-seed.sql` (prints the session id). The seed inserts `vendor_disabled:apollo` and `vendor_disabled:hunter`, so it aborts on `settings_pkey` after [admin settings](admin-settings.md) added that row: delete the row first. The dev seed has a chat with the same title, so take the id with `WHERE user_id = <ale's id>`. Sign in as the admin; `/admin` is not behind onboarding.

- **Transcript.** `bin/browser goto "$VERIFY_WEB/admin/chat-sessions/<id>"`, `wait text "Riepilogo"`. The «Job» value in the summary links to `/admin/jobs?job=<id>#job-<id>`: Jobs filtered to that job, its row open. `ax` lists `DisclosureTriangle "Tool: search_companies Fatto 31 aziende apollo 12 cr"`, `"Tool: find_people Fatto 47 persone 100 cr"` (no vendors: the old shape) and `"Tool: enrich_email fallito apollo → hunter 0 cr"`, then three more `enrich_email` calls: `"Tool: enrich_email Da riprovare 3 ricerche non riuscite 0 cr"` (3 of 3 failed, no «0 email»), `"Tool: enrich_email Fatto 0 email · 1 da riprovare 0 cr"` (1 of 10) and `"Tool: enrich_email Fatto 0 email 0 cr"` (none failed), the question text and its options. Summary: `Crediti` `538 spesi · 14 resi` and `Netto` `524` (the two jobs), `Costo per noi` with `LLM` and `Fornitori (stima)` `1,60 $`, `Ricavo stimato` `8,38 €` (524 × €16/1000) and the margin `6,96 € · 83%`.
- **Views.** `click link "Solo chiamate ai tool"`, `wait-url tools=1`; `click link "Apri tutti i dettagli"`, `wait-url open=1`: only the tool-call message is left, each with its JSON open.
- **Costs.** `goto "$VERIFY_WEB/admin/costs"`, `wait text "Fornitori di contatti"`. The chart is an `image` whose name sums the window («Grafico a linee dal … al …: ricavi …, margine ….»); each line has its name at its end (Ricavi, Fornitori, LLM) and LLM is dashed. Lines that end on the same value stack their names: with the seed's `vendor_calls` and `llm_usage` moved to yesterday (`UPDATE … SET created_at = now() - interval '1 day'`), Fornitori and LLM both end at 0 and their labels sit 14 px apart. `bin/browser` has no hover: dispatch `mousemove` on `.recharts-wrapper` with `eval` to read the tooltip, which ends with a «Margine» row. The table view adds a «Margine» column. A provider whose switch is on carries `link "<provider> disattivato: apri l'interruttore in Impostazioni"` (its visible text is only «disattivato») to `/admin/settings#vendor_disabled:<provider>`. Nothing inside the chart `image` is a tab stop: `press Tab` goes from `link "Mostra tabella"` straight to the provider link, and `eval` `document.querySelectorAll('[role=img] [tabindex="0"]').length` is 0 (Recharts' wrappers keep `tabindex=-1`, which Tab skips). The table view is the keyboard way to the values. `click link "Mostra tabella"`, `click link "Margine più basso"` → `?view=table&sort=margin`.
- **Costs error.** `bin/stack compose stop api`, `goto` costs: the alert as above (the rail counters disappear: they fail open). `bin/stack compose start api`, wait a few seconds, `click link "Riprova"` and `wait text "Fornitori di contatti"`.
- **Jobs.** `goto "$VERIFY_WEB/admin/jobs"`. Chips read `Tutti 4`, `Serve input 1`, `Riuscito 2`, `Fallito 1`. `click button "Dettagli <8 chars of the failed job>"` opens its row: `BRIEF`, `ERRORE` `hunter: timeout dopo 3 tentativi (30s)`, `3 righe non consegnate, 14 crediti resi`, and `FASI` `Trova persone 2:30`, `Email verificate 64/100 · 14:55`. `click link "Fallito 1"` → `?status=failed` and one row. The rail reads `Job 2` (the failed and the needs-input job).
- **Chat outcomes, plan and company (#352).** On ale's user page the header reads `ale@verify.local · Rossi Comunicazione · dal …` and `Piano Pro · si rinnova il <today + 20 days>`; `?tab=chats` lists the three chats with Esito `0 persone · 31 aziende` / `Bloccata` / `Nessun risultato` and Crediti `524` / `0` / `6`.
- **Vendor errors (#352).** On `/admin/settings` the `vendor_disabled:hunter` row is tinted with `3 errori in 24 h`, and a note above the list names `pdl (1)`, a failing vendor with no switch. `GET /v1/admin/settings` carries `vendor_errors`.
- **Jobs filters.** Push ale's jobs off the first page: `bin/stack psql -tAc "INSERT INTO jobs (organization_id, user_id, status, created_at) SELECT default_organization(u.id), u.id, 'succeeded', now() - g * interval '1 second' FROM generate_series(1,60) g, (SELECT id FROM \"user\" WHERE email='adm@verify.local') u"`. From the transcript, `click text "<8 chars of the job id>"`: `wait-url job=`, one row with its `Dettagli` button `aria-expanded="true"`, chip `Job …`. `click link "Togli il filtro Job …"` → `/admin/jobs` with 50 rows, the old job not among them. On ale's user page, `click css 'main a[href^="/admin/jobs?user="]'` (`link "Job"` also matches the rail): chip `Utente ale@verify.local`, `Tutti 4`. `click link "Fallito 1"` keeps `user=`; clearing the chip keeps `status=failed`.

## Gotchas

- The rail links' names include the counters' sr-only text, so `link "Impostazioni"` does not match while a switch is on: `goto` the page or use the full name.
- Vendor cost per chat is the user's `vendor_calls` inside the window of one of the chat's jobs (there is no job id on `vendor_calls`); the seed puts its calls inside the first job.
- `--full` screenshots stop at the viewport: the page scrolls inside the shell. Scroll with `bin/browser eval "document.querySelector('main').parentElement.parentElement.scrollTo(0, 2000)"`.
- The jobs list does not refresh by itself (no polling): reload it.
- The seed writes `settings` rows: `vendor_disabled:aiark` on, `apollo` and `hunter` off, and `signup_bonus_credits` 100. Every user who signs up afterwards gets 100 credits, not 25, and [admin settings](admin-settings.md) lists these rows.
